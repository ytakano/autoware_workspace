\section{Introduction}
\label{sec:intro}

Autoware~\cite{autoware} localizes a vehicle by aligning each LiDAR scan to a Gaussian
voxel map with the Normal Distributions Transform (\ndt)~\cite{biber2003ndt}. At 10\,Hz,
each alignment has a \SI{100}{ms} period before a late pose forces downstream estimation toward
dead reckoning. Yet input geometry changes Newton iterations, neighbor multiplicity, and
kd-tree traversal. Across the synthetic stress inputs, the lowest engine--fixture median is
\SI{\tailsMinMedian}{ms}, whereas the largest observed latency is
\SI{\tailsMaxObserved}{ms} on the same core, a \tailsLatencySpread-fold span. Nominal
replay therefore cannot answer whether the deadline has defensible margin.

Classical static WCET analysis struggles because the dominant bounds are input properties;
exhaustive enumeration is infeasible, while wall-clock-guided fuzzing is noisy and
machine-specific. We instead separate a structural work envelope from measured
platform cost, then search deterministic work counters for stress witnesses.

Rust is useful here not because C++ cannot be bounded, but because ownership, lifetimes, and
aliasing rules discharge memory-safety and data-race-freedom obligations in the safe
core~\cite{jung2018rustbelt}. This narrows project-specific validation to equivalence,
numerics, work bounds, and timing. The reduction excludes the FFI, unsafe code, and trusted
dependencies. The port also builds as \texttt{no\_std} for real-time environments without
the standard library. Its radius query caps neighbors at \maxnn; the
\emph{bounded-neighbor domain} $D$ contains inputs whose uncapped queries already satisfy
that limit. Per-input work traces compare a defined work shape on evaluated inputs; leaf
payloads, traversal, memory operations, and latency are assessed separately.

The objective is to realize a real-time-oriented \ndt{} engine through the Rust port, with
explicit work limits and timing evidence for its critical path. The production C++ engine
serves as the behavioral and timing baseline for the port. We do not attempt to search or
establish the C++ implementation's worst traversal shape.

Our contributions are:
\begin{enumerate}
  \item A three-layer analysis combining a property-tested structural work bound,
    deterministic stress-witness generation using Rust counters, and controlled timing of
    frozen witnesses.
    Mandatory tail diagnostics determine whether extrapolation is admissible and reject it
    for these measurements.
  \item A per-input cross-language work-trace conformance check. The base-agreement set
    $E_{\mathrm{base}}$ checks iteration equality and pose and score tolerances;
    $E_{\mathrm{shape}}$ additionally checks the recorded
    pass structure, point and neighbor counts, and canonical leaf identities. A separate
    payload digest checks leaf means and inverse covariances. Neither establishes runtime
    membership in $D$ or full semantic equivalence.
  \item A domain-informed construction that reaches the Rust envelope's
    $P\maxnn(N_{\mathrm{iter}}{+}1)$ maximum for the common kernel-evaluation term,
    followed by a counter-guided search that raises the Rust implementation's kd-node count
    by \searchKdGrowthPct\%; frozen Pareto alternatives use the same timing protocol.
  \item An industrial case study in which Rust removes the C++ per-point allocation hazard
    within reserved capacities. In the unified three-boot campaign, the largest recorded
    values are \SI{\unifiedFixtureMaxCpp}{ms} for C++ and
    \SI{\unifiedFixtureMaxRust}{ms} for Rust, with a smaller Rust maximum on all
    \tailsRustFasterCount{}
    fixtures. Contract-geometry and
    shipped-configuration witnesses separate production input constraints from
    configuration effects, while a single-drive replay exposes the residual conformance
    boundary.
\end{enumerate}

The remainder of this paper is organized as follows. Section~\ref{sec:problem}
formulates the WCET problem and its structural work decomposition.
Sections~\ref{sec:methodology} and~\ref{sec:implementation} present the three-layer
method, cross-language work-trace conformance check, and implementation, while
Section~\ref{sec:evaluation} reports stress-witness generation, timing, trace, real-data,
and cross-ISA results. Sections~\ref{sec:threats} and~\ref{sec:related} discuss limitations
and prior
work, respectively. Section~\ref{sec:conclusion} presents the conclusions, and the appendix
provides detailed regression and cross-ISA diagnostics, together with the tail-model
rejection details.
