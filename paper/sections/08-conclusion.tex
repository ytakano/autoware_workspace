\section{Conclusion}
\label{sec:conclusion}

A high-fidelity port turns analysis of a data-dependent industrial kernel into three
separable obligations: enforce and test a work envelope, search deterministic counters for
stress witnesses, and measure frozen inputs. Per-input traces transfer common semantic work
to unmodified C++ without equating implementation-specific traversal or latency. The search
saturates the dominant kernel term; the Rust port removes the per-point allocation hazard
within reserved capacities and has no larger observed maximum on shared fixtures. Timing
remains empirical.

Rust is not necessary for these bounds. Its safe core narrows memory-safety and race
obligations so validation can focus on equivalence, numerics, work, and timing; FFI, unsafe
code, and dependencies remain trusted.

Operational validation is therefore still required: the component results do not establish
production readiness. Deployment requires the production ECU, representative maps, scans, initial guesses, and co-resident Autoware loads;
measurements must cover governor behavior, multi-core interference, end-to-end 10\,Hz
compliance, and closed-loop quality gates and filter innovations. The host parallel result
is deadline feasibility, not multi-core WCET. Analytical or probabilistic timing claims
also require, respectively, a deployment cost bound or an independence-preserving protocol.
