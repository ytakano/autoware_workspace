\section{Methodology}
\label{sec:methodology}

Three analysis layers establish a work bound, search for counter-extremal inputs, and
measure frozen witnesses. Per-input cross-language traces check recorded common-work
conformance before timing, and a cross-ISA replay checks transfer to the deployment-class
target.

\subsection{Analysis layer 1: Structural bound and property tests}
Given caller contracts on $P$ and $N_{\mathrm{leaves}}$, loop guards, the \maxnn{} cap,
and pre-reserved buffers enforce Eq.~\eqref{eq:decomp}. Randomized property tests check
$\mathrm{passes}\le N_{\mathrm{iter}}+1$,
$\mathrm{points}=P\,\mathrm{passes}$,
$\sumnbr\le\mathrm{points}\,\maxnn$, and
$\kdnodes\le\mathrm{points}\,N_{\mathrm{leaves}}$.
Within the reserved envelope, a counting allocator verifies allocation freedom from the
first frame; linting and an explicit fixed-depth kd stack enforce panic- and
recursion-freedom.

\subsection{Analysis layer 2: Counter-guided extremal-input search}
\label{sec:meth-search}
Compile-time instrumentation counts passes, points, \sumnbr, and \kdnodes; disabled counters
compile away. A seeded hill-climb mutates tile overlap and extent, centroid geometry, source
composition, initial guess, and convergence threshold to maximize
$(N_{\mathrm{iter}},\sumnbr,\kdnodes)$ lexicographically. $P$ remains a caller contract,
not a search dimension. Deterministic fitness makes results reproducible and
platform-independent. Because lexicographic order need not match time order, all
non-dominated counter vectors are archived and their fixtures timed. Budget-matched random
and wall-clock-fitness arms test search effectiveness.

\subsection{Cross-language transfer: Per-input work-trace conformance}
\label{sec:meth-transfer}
The shipped C++ sources remain byte-identical. A local analysis build and the Rust port
instead emit matched per-pass traces; the same fixture bytes then run on the unmodified C++
binary for timing. Floating-point streams need not be bit-identical because FLANN returns
distance-sorted neighbors while Rust uses kd-visit order.

Three definitions limit the comparison. The \textbf{bounded-neighbor domain} $D$ contains
inputs whose uncapped queries return at most \maxnn{} leaves; the capped Rust query does not
report a 65th leaf, so the trace check does not prove membership in $D$. The
\textbf{base-agreement set} $E_{\mathrm{base}}$ requires equal iterations and recorded
pose/score agreement. The stricter \textbf{work-trace-conformant set}
$E_{\mathrm{trace}}\subseteq E_{\mathrm{base}}$ also requires equal pass structure,
points per pass, neighbor-evaluation counts, and per-point FNV-1a hashes of neighbor-leaf
mean bits. These fields define
\[
 \begin{aligned}
 W_{\mathrm{common}}=(&\text{passes},\text{points/pass},\\
 &\text{neighbor evaluations},\text{neighbor count/hash}).
 \end{aligned}
\]
For an evaluated input, work-trace conformance means equality of this recorded structure in
addition to base agreement. It does not imply full semantic equivalence, membership in $D$,
or equal total work. Hash collisions remain possible, so equality is evidence rather than a
formal set proof. C++ FLANN traversal, result containers, and allocation and Rust kd
traversal and flat buffers are outside $W_{\mathrm{common}}$; each engine therefore has a
separate work-model instance. A conformant transferred fixture is a shared timing witness,
not proof of equal stress.

All synthetic fixtures satisfy the full work-trace criterion. Real replay separates
\realTraceAll{} work-trace-conformant, \realBaseOnly{} base-only, and
\realIterationDivergent{} iteration-divergent frames. An independent production-binary
allocation count also reconstructs C++ point/pass work to \allocCertSpreadPct\% on every
neighbor-returning fixture, but does not establish conformance of the full tuple.

\subsection{Analysis layer 3: Measurement and \pwcet}
Frozen little-endian fixtures feed both engines through one replay harness. An
\texttt{LD\_PRELOAD} interposer counts C++ allocations without source changes. Regression
against engine-specific counters is diagnostic only. Per-session POT/GPD fitting uses
maximum likelihood, bootstrap intervals, and a mandatory diagnostic gate; extrapolation is
reported only when assumptions hold.

\subsection{Cross-ISA transfer: Deployment-target validation}
\label{sec:meth-crossisa}
Pure-Rust \texttt{libm} removes dependence on the platform C library. Replaying frozen
fixtures on a Raspberry Pi~4 bare-metal \texttt{no\_std} kernel reproduces all
\raspiTotal{} counter tuples exactly after correcting one stale expected snapshot. This
checks each fixture rather than assuming ISA independence; Sec.~\ref{sec:eval-raspi4}
reports timing and Appendix~\ref{app:crossisa-debug} the discrepancy diagnosis.
