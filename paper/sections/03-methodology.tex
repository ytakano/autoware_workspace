\section{Methodology}
\label{sec:methodology}

The analysis has three layers: a structural work bound that is enforced and machine-checked
(Layer~1), a deterministic search for inputs that realize it (Layer~2), and measurement with a
statistical tail model on the frozen worst inputs (Layer~3). A transfer argument connects the
instrumented Rust engine to the unmodified C++ engine, and a second one connects the host to
the deployment target.

\subsection{Layer 1: structural bound, machine-checked}
Every term of \eqref{eq:decomp} is enforced by construction in the Rust engine (static loop
guards, the hard \maxnn{} search cap, pre-reserved buffers) and \emph{machine-checked} by
property-based tests over randomized maps, clouds, and parameters: for every sampled input,
$\mathrm{passes} \le N_{\mathrm{iter}}{+}1$, $\mathrm{points} = \mathrm{passes} \cdot P$,
$\sumnbr \le \mathrm{points} \cdot \maxnn$, and $\kdnodes \le \mathrm{points} \cdot
N_{\mathrm{leaves}}$. The real-time path is additionally allocation-free from the first frame
(verified by a counting allocator), recursion-free (a fixed-depth explicit stack), and
panic-free (lint-enforced): the properties that make a finite bound possible at all
(Sec.~\ref{sec:threats}).

\subsection{Layer 2: counter-guided worst-input search}
\label{sec:meth-search}
We instrument the engine with four \emph{deterministic algorithmic cost counters} (derivative
passes, points processed, \sumnbr, and \kdnodes; Sec.~\ref{sec:decomposition}) behind a
compile-time feature whose disabled form compiles to nothing. A seeded hill-climb mutates a
parameterized input generator (map tile overlap, map extent, centroid crowding vs.\ surface
roughness, source composition, initial-guess offset, convergence threshold) and maximizes
the lexicographic counter vector $(N_{\mathrm{iter}}, \sumnbr, \kdnodes)$. Because the
fitness is a pure function of the input, the search is reproducible, and its result is a
property of the \emph{algorithm}, not of the measurement machine. $P$ is deliberately
\emph{not} a search freedom: it is a caller-side cap, and searching it would saturate
trivially while masking the interesting terms.

A lexicographic scalarization need not rank the \emph{time}-worst input first: an input with
fewer kernel evaluations but heavier traversal could be slower. The search therefore
additionally archives the non-dominated (Pareto) frontier over the counter vector across
\emph{all} evaluations, and every frontier member is frozen and timed under the same
controlled protocol as the champion. The search protocol itself is ablated (hill-climb vs.\
budget-matched random sampling, counter vs.\ wall-clock fitness, across seeds) in
Sec.~\ref{sec:eval-search}.

\subsection{Cross-language transfer via bit-exactness}
\label{sec:meth-transfer}
The C++ sources must remain byte-identical (an upstream constraint), so they cannot be
instrumented. Instead we rely on bit-exactness: the Rust port reproduces the C++ engine's
floating-point operand stream, and hence its iteration counts, neighbor sets, and
\emph{work}. This is validated by a differential test suite that runs both engines on
identical inputs and requires exactly equal iteration counts and near-exact poses and
scores. The equivalence holds on the \textbf{bounded-neighbor domain} $D$: the set of
inputs whose every radius query returns at most \maxnn{} in-range leaves, so that the
port's hard cap never truncates. Sec.~\ref{sec:implementation} shows that all
preprocessing-reachable inputs (and everything short of three adversarially crowded
overlapping tiles) lie in $D$. Every worst-case claim that crosses languages in this paper
is a claim \emph{over $D$}: a worst input discovered on the instrumented Rust engine is a
worst input for the C++ engine over $D$ by construction. Outside $D$ the engines
intentionally diverge; the C++ engine's neighbor set, and with it its cost, grows without
bound with tile multiplicity, which we report as a structural hazard of the uncapped
implementation (Sec.~\ref{sec:implementation}), not as a bounded quantity.

Rather than trusting membership globally, the replay harness \emph{re-certifies it per
input} at measurement time by asserting equal \texttt{iteration\_num} across engines and,
on the frozen fixtures, agreement of the final pose and both convergence scores (the
real-data replay of Sec.~\ref{sec:eval-realdata} currently certifies the iteration leg
only). A mismatch flags that input instead of silently comparing unequal work, and the same
assertion doubles as the runtime membership check for $D$, since truncation breaks equal
work. This certification proved necessary in practice: on real map data it caught two
port-fidelity gaps that the synthetic suite could not see, leaving a characterized residual
of \realDivergences{} frames (Secs.~\ref{sec:eval-realdata} and~\ref{sec:threats}).

A second, independent certificate leg requires no instrumentation at all. The C++ engine's
allocation count, read from the untouched production binary by the \texttt{LD\_PRELOAD}
interposer, is a deterministic function of its per-point work: it re-derives $P \cdot
N_{\mathrm{pass}}$ on the C++ side and agrees with the Rust counters to
\allocCertSpreadPct\% on every neighbor-returning fixture (Sec.~\ref{sec:eval-alloc}), a
resolution that would expose even a single extra derivative pass. (An instrumented C++
\emph{analysis} build could add full trace hashes; the byte-identical constraint governs
the shipped sources, not local analysis builds. We prioritize certificates obtainable from
the production binary itself.)

\subsection{Layer 3: measurement and \pwcet}
Worst inputs are frozen in a self-contained little-endian binary format readable from both
languages, so the exact same bytes feed every experiment (the map is stored as tiles;
Sec.~\ref{sec:impl-fixtures} explains why tile overlap is the $K$-adversarial case). A single
replay binary drives both engines on identical buffers. Heap allocations are counted by an
\texttt{LD\_PRELOAD} interposer whose hooks the replay discovers via \texttt{dlsym}, requiring
no upstream edits. We then (i)~regress median latency against the counters, $T \approx
a\cdot\sumnbr + b\cdot\kdnodes + c$, giving directly comparable per-operation costs for the
two implementations, and (ii)~run a peaks-over-threshold extreme-value analysis (the
methodology of measurement-based probabilistic timing analysis, MBPTA) with maximum
likelihood, bootstrap confidence intervals, and the full diagnostic checklist of our
measurement policy; extrapolated exceedance claims are made \emph{only if the diagnostics
hold} (Sec.~\ref{sec:eval-evt}).

\subsection{Cross-ISA transfer to the deployment target}
\label{sec:meth-crossisa}
The Rust engine routes every transcendental through a pure-Rust \texttt{libm} implementation
(including inside its linear-algebra library), targeting floating-point results that are
independent of the instruction-set architecture and of the platform's C library. The frozen
fixtures and their counter values therefore carry over to the bare-metal deployment target
unchanged, and the transfer is \emph{checkable} there by re-running the counters and
asserting equality: the same per-input certification as the cross-language comparison.

We executed this protocol on the deployment hardware, a Raspberry Pi~4 running the
bare-metal \texttt{no\_std} kernel: the counters transfer \emph{exactly} on all
\raspiTotal{} frozen fixtures. (One fixture initially flagged; bisection traced the
mismatch to a stale host-side expectation snapshot, not to the ISA;
Sec.~\ref{sec:eval-raspi4}.) The \texttt{libm} choice also costs a bounded, measured loss
of parity with the host C++ engine (Sec.~\ref{sec:threats}).
