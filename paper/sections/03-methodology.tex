\section{Methodology}
\label{sec:methodology}

The analysis has three layers: a structural work bound that is enforced and machine-checked
(Layer~1), a deterministic search for inputs that realize it (Layer~2), and measurement with a
statistical tail model on the frozen worst inputs (Layer~3). A transfer argument connects the
instrumented Rust engine to the unmodified C++ engine, and a second one connects the host to
the deployment target.

\subsection{Layer 1: structural bound, machine-checked}
Every term of \eqref{eq:decomp} is enforced by construction in the Rust engine (static loop
guards, the hard \maxnn{} search cap, pre-reserved buffers) and \emph{machine-checked} by
property-based tests over randomized maps, clouds, and parameters: for every sampled input,
$\mathrm{passes} \le N_{\mathrm{iter}}{+}1$, $\mathrm{points} = \mathrm{passes} \cdot P$,
$\sumnbr \le \mathrm{points} \cdot \maxnn$, and $\kdnodes \le \mathrm{points} \cdot
N_{\mathrm{leaves}}$. The real-time path is additionally allocation-free from the first frame
(verified by a counting allocator), recursion-free (a fixed-depth explicit stack), and
panic-free (lint-enforced) --- the properties that make a finite bound possible at all
(Sec.~\ref{sec:threats}).

\subsection{Layer 2: counter-guided worst-input search}
\label{sec:meth-search}
We instrument the engine with four \emph{deterministic algorithmic cost counters} ---
derivative passes, points processed, \sumnbr, and \kdnodes{}
(Sec.~\ref{sec:decomposition}) --- behind a compile-time feature whose disabled form compiles
to nothing. A seeded hill-climb mutates a parameterized input generator (map tile overlap,
map extent, centroid crowding vs.\ surface roughness, source composition, initial-guess
offset, convergence threshold) and maximizes the lexicographic counter vector
$(N_{\mathrm{iter}}, \sumnbr, \kdnodes)$. Because the fitness is a pure function of the input,
the search is reproducible, and its result is a property of the \emph{algorithm}, not of the
measurement machine. $P$ is deliberately \emph{not} a search freedom: it is a caller-side cap,
and searching it would saturate trivially while masking the interesting terms.

\subsection{Cross-language transfer via bit-exactness}
\label{sec:meth-transfer}
The C++ sources must remain byte-identical (an upstream constraint), so they cannot be
instrumented. Instead we rely on bit-exactness: the Rust port reproduces the C++ engine's
floating-point operand stream --- validated by a differential test suite that runs both
engines on identical inputs and requires exactly equal iteration counts and near-exact poses
and scores --- hence identical iteration counts, neighbor sets, and \emph{work} on any input.
A worst input discovered on the instrumented Rust engine is therefore a worst input for the
C++ engine by construction. Rather than trusting this globally, the replay harness
\emph{re-certifies it per input} at measurement time by asserting equal
\texttt{iteration\_num} across engines; a mismatch flags that input instead of silently
comparing unequal work. This certification is load-bearing: on real map data it caught two
port-fidelity gaps that the synthetic suite could not see, and after fixing them it bounds the
remaining divergence at $0.12\%$ of frames (Secs.~\ref{sec:eval-realdata}
and~\ref{sec:threats}).

\subsection{Layer 3: measurement and \pwcet}
Worst inputs are frozen in a self-contained little-endian binary format readable from both
languages, so the exact same bytes feed every experiment (the map is stored as tiles;
Sec.~\ref{sec:impl-fixtures} explains why tile overlap is the $K$-adversarial case). A single
replay binary drives both engines on identical buffers. Heap allocations are counted by an
\texttt{LD\_PRELOAD} interposer whose hooks the replay discovers via \texttt{dlsym}, requiring
no upstream edits. We then (i)~regress median latency against the counters, $T \approx
a\cdot\sumnbr + b\cdot\kdnodes + c$, giving directly comparable per-operation costs for the
two implementations, and (ii)~fit a Gumbel distribution --- the extreme-value-theory (EVT) family used by
measurement-based probabilistic timing analysis (MBPTA) --- to per-fixture block maxima for
comparative probabilistic-WCET (\pwcet) exceedance estimates. We use the fit for
\emph{comparison}, not certification (Sec.~\ref{sec:threats}).

\subsection{Cross-ISA transfer to the deployment target}
The Rust engine routes every transcendental through a pure-Rust \texttt{libm} implementation
(including inside its linear-algebra library), making its floating-point results independent
of the instruction-set architecture and of the platform's C library; the frozen fixtures and
their counter values therefore transfer to the AArch64 bare-metal deployment target, where
equal work is re-verified by comparing counters. (The same choice costs a bounded, measured
sliver of host C++ parity; Sec.~\ref{sec:threats}.)
