\section{Methodology}
\label{sec:methodology}

Three analysis layers establish a conditional work bound, search for Rust-counter stress
inputs, and measure frozen witnesses. Per-input cross-language traces check recorded work-trace
conformance before timing, and a cross-ISA replay checks transfer to the deployment-class
target.

\subsection{Analysis layer 1: Structural bound and property tests}
\paragraph{Conditional work-envelope proposition.}
Let $P\le P_{\max}=\runtimePMax$, $N_{\mathrm{leaves}}\le
L_{\max}=\runtimeLeavesMax$, $N_{\mathrm{iter}}\le I_{\max}=30$, and
$K(p)\le\maxnn=64$. Assume line-search refinement is disabled, the balanced kd-tree fits
the 64-entry query stack, all scalar and point inputs are finite, and caller-owned scratch
has been reserved for $(P_{\max},I_{\max})$. Checked construction also requires the
integer products below to fit in their counter types. Then the serial Rust align kernel
satisfies
\begin{equation}
 \begin{aligned}
 N_{\mathrm{pass}}&\le31,\qquad
 \sumnbr\le31P_{\max}\maxnn,\\
 \kdnodes&\le31P_{\max}L_{\max}.
 \end{aligned}
 \label{eq:rust-envelope}
\end{equation}
For the configured limits, these bounds are 3,968,000 kernel evaluations and
25,916,000,000 kd-node visits. The project-owned serial kernel performs no heap allocation,
lock acquisition, or recursive call after entry. Capacity, arithmetic, stack, iteration,
map-size, and non-finite-input violations return typed errors. A query that finds a 65th
in-radius leaf retains the first 64, records a diagnostic, and forces the result to
non-converged so the node can issue a warning and reject convergence. Fixed-size linear
algebra and other dependencies remain trusted; this proposition is not a formal proof of
their internals or of elapsed time.

Randomized property tests check
$\mathrm{passes}\le N_{\mathrm{iter}}+1$,
$\mathrm{points}=P\,\mathrm{passes}$,
$\sumnbr\le\mathrm{points}\,\maxnn$, and
$\kdnodes\le\mathrm{points}\,N_{\mathrm{leaves}}$. A counting allocator verifies zero
allocations from the first frame inside the declared envelope. Linting excludes explicit
panic paths in project code, and differential tests compare the fixed-stack query against
a recursive test oracle.

\subsection{Analysis layer 2: Rust counter-guided stress search}
\label{sec:meth-search}
Compile-time instrumentation in the Rust port counts passes, points, \sumnbr, and
\kdnodes; disabled counters compile away. A seeded hill-climb mutates tile overlap and
extent, centroid geometry, source composition, initial guess, and convergence threshold to
maximize $(N_{\mathrm{iter}},\sumnbr,\kdnodes)$ lexicographically. This
\emph{engine-configuration stress} search jointly varies input geometry and configuration;
it is not an input-only search under shipped parameters. $P$ remains a caller contract,
not a search dimension. A separate \emph{shipped-configuration stress} search fixes
$\epsilon=0.01$ and enforces the production preprocessing input contracts. The counter
fitness is independent of wall-clock timing and reproducible for the fixed Rust
implementation. Because lexicographic order need not match time order, all non-dominated
counter vectors are archived and their fixtures timed. Budget-matched random and
wall-clock-fitness arms test search effectiveness.

Only \sumnbr{} is a common work axis across the two engines. The \kdnodes{} objective is
specific to the Rust kd-tree; the search does not optimize the C++ FLANN distance or
plane-evaluation counters. Replaying the resulting fixtures on C++ provides a port baseline
and timing observations over the transferred set, not evidence of a C++ traversal extremum.

\subsection{Cross-language transfer: Per-input work-trace conformance}
\label{sec:meth-transfer}
The shipped C++ sources remain byte-identical. A local analysis build and the Rust port
instead emit matched per-pass traces; the same fixture bytes then run on the unmodified C++
binary for timing. Floating-point streams need not be bit-identical because FLANN returns
distance-sorted neighbors while Rust uses kd-visit order.

Three definitions limit the comparison. The \textbf{bounded-neighbor domain} $D$ contains
inputs for which every radius query generated by the capped Rust execution would return at
most \maxnn{} leaves if evaluated without the cap at the same query coordinate. The C++
analysis build performs uncapped searches and records each complete returned list before
kernel evaluation.

Subscripts $C$ and $R$ denote the C++ analysis build and the Rust engine. For an evaluated
input fixture $x$, let $N_{\mathrm{iter}}^e$, $t_e$, $q_e$, $\pi_e$, and $\lambda_e$
denote, respectively, engine $e\in\{C,R\}$'s completed Newton updates, output
translation, normalized output quaternion, transformation probability, and nearest-voxel
transformation likelihood. Suppressing the dependence on $x$, define
\[
 \Delta_t=\lVert t_C-t_R\rVert_2,\qquad
 \Delta_R=2\arccos |\langle q_C,q_R\rangle|,
\]
with $\Delta_{\mathrm{tp}}=|\pi_C-\pi_R|$ and
$\Delta_{\mathrm{nvtl}}=|\lambda_C-\lambda_R|$. The
\textbf{base-agreement set} is
\[
 E_{\mathrm{base}}=\{x:N_{\mathrm{iter}}^C=N_{\mathrm{iter}}^R\
 \ \text{and}\ \Delta_j\le\tau_j\ \text{for every}\ j\in J\}.
\]
Here $j$ indexes the comparison metrics in
$J=\{t,R,\mathrm{tp},\mathrm{nvtl}\}$, and $\tau_j$ is the corresponding threshold:
$\tau_t=10^{-4}\,\mathrm{m}$, $\tau_R=10^{-5}\,\mathrm{rad}$, and
$\tau_{\mathrm{tp}}=\tau_{\mathrm{nvtl}}=10^{-4}$.
All quantities must also be finite. These fixed numerical-agreement thresholds are much
smaller than operational localization tolerances; they are comparison criteria, not
production acceptance limits.

Each map leaf receives a canonical identifier $(g,v)$, where $g$ is the ordinal of its
grid in the deterministically sorted map and $v$ is its signed voxel key. Before hashing,
each point's returned leaves are sorted by this identifier. A domain-separated SHA-256
digest preserves point and pass order while recording the sorted identifier list. The work
trace for one engine is
\[
 W_{\mathrm{shape}}=
 \left(N_{\mathrm{pass}},
 \left(P_i,S_{\mathrm{nbr},i},\mathbf H_{\mathrm{ID},i}\right){}_
 {i=1}^{N_{\mathrm{pass}}}\right).
\]
Here $i$ indexes derivative-evaluation passes, $P_i$ is the number of source points
processed in pass $i$, $S_{\mathrm{nbr},i}$ is that pass's point--leaf evaluation count,
and $\mathbf H_{\mathrm{ID},i}$ is the point-ordered sequence of canonical-ID digests.
The \textbf{trace-conformant set} is
\[
 E_{\mathrm{shape}}=
 \{x\in E_{\mathrm{base}}:
 W_{\mathrm{shape}}^C(x)=W_{\mathrm{shape}}^R(x)\}.
\]
A second SHA-256 payload digest includes each leaf ID, mean, and regularized inverse
covariance. It is reported independently and is not part of $E_{\mathrm{shape}}$.
This distinction prevents shape equality from being interpreted as equality of all
kernel operands.

Because the C++ search is uncapped, membership in $E_{\mathrm{shape}}$ shows that every
corresponding C++ query returned at most \maxnn{} leaves. It does not establish membership
in $D$, however, because floating-point differences can give the engines slightly
different transformed points and query coordinates. A C++ query can return 64 leaves while
the Rust coordinate admits a 65th; the capped Rust trace still contains only its first 64.
The Rust engine separately reports that 65th leaf as a runtime diagnostic; the diagnostic
is not part of $E_{\mathrm{shape}}$.

Work-trace conformance is a dynamic check on each evaluated input. It does not imply full
semantic equivalence, membership in $D$, or equal total work. SHA-256 collision risk is
computational rather than a formal impossibility, and the selected payload still does not
record every execution state. C++ FLANN traversal, result containers, and allocation
behavior, together with Rust kd-tree traversal and flat-buffer operations, are outside
$W_{\mathrm{shape}}$; each engine therefore
has a separate work-model instance. A conformant transferred fixture is a shared timing
witness, not proof of equal stress.

\subsection{Analysis layer 3: Controlled measurement of frozen witnesses}
Frozen little-endian fixtures feed both engines through one replay harness in documented
host configurations. An \texttt{LD\_PRELOAD} interposer counts C++ allocations without
source changes. Regression against engine-specific counters is diagnostic only. Tail-model
fitting is also secondary to the observed timing results: per-session POT/GPD fits use
maximum likelihood and bootstrap intervals, but a mandatory gate requires independence and
stability before any extrapolation may be reported.

\subsection{Cross-ISA transfer: Deployment-target validation}
\label{sec:meth-crossisa}
Pure-Rust \texttt{libm} removes dependence on the platform C library. We replay the frozen
fixtures on a Raspberry Pi~4 bare-metal \texttt{no\_std} kernel and compare each counter
tuple with its host value rather than assuming ISA independence. Section~\ref{sec:eval-raspi4}
reports the results, and Appendix~\ref{app:crossisa-debug} gives the discrepancy diagnosis.
