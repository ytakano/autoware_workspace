\section{Methodology}
\label{sec:methodology}

Three analysis layers establish a work bound, search for counter-extremal inputs, and
measure frozen witnesses. Per-input cross-language traces check recorded work-shape
conformance before timing, and a cross-ISA replay checks transfer to the deployment-class
target.

\subsection{Analysis layer 1: Structural bound and property tests}
Given caller contracts on $P$ and $N_{\mathrm{leaves}}$, loop guards, the \maxnn{} cap,
and pre-reserved buffers enforce Eq.~\eqref{eq:decomp}. Randomized property tests check
$\mathrm{passes}\le N_{\mathrm{iter}}+1$,
$\mathrm{points}=P\,\mathrm{passes}$,
$\sumnbr\le\mathrm{points}\,\maxnn$, and
$\kdnodes\le\mathrm{points}\,N_{\mathrm{leaves}}$.
Within the reserved envelope, a counting allocator verifies allocation freedom from the
first frame; linting and an explicit fixed-depth kd stack enforce panic- and
recursion-freedom.

\subsection{Analysis layer 2: Counter-guided extremal-input search}
\label{sec:meth-search}
Compile-time instrumentation counts passes, points, \sumnbr, and \kdnodes; disabled counters
compile away. A seeded hill-climb mutates tile overlap and extent, centroid geometry, source
composition, initial guess, and convergence threshold to maximize
$(N_{\mathrm{iter}},\sumnbr,\kdnodes)$ lexicographically. $P$ remains a caller contract,
not a search dimension. Deterministic fitness makes results reproducible and
platform-independent. Because lexicographic order need not match time order, all
non-dominated counter vectors are archived and their fixtures timed. Budget-matched random
and wall-clock-fitness arms test search effectiveness.

\subsection{Cross-language transfer: Per-input work-shape conformance}
\label{sec:meth-transfer}
The shipped C++ sources remain byte-identical. A local analysis build and the Rust port
instead emit matched per-pass traces; the same fixture bytes then run on the unmodified C++
binary for timing. Floating-point streams need not be bit-identical because FLANN returns
distance-sorted neighbors while Rust uses kd-visit order.

Three definitions limit the comparison. The \textbf{bounded-neighbor domain} $D$ contains
inputs whose uncapped queries return at most \maxnn{} leaves; the capped Rust query does not
report a 65th leaf, so the trace check does not prove membership in $D$. For normalized
output quaternions $q_C,q_R$, define
\[
 \Delta_t=\lVert t_C-t_R\rVert_2,\qquad
 \Delta_R=2\arccos |\langle q_C,q_R\rangle|,
\]
and let $\Delta_{\mathrm{tp}}$ and $\Delta_{\mathrm{nvtl}}$ be absolute differences in
transformation probability and nearest-voxel transformation likelihood. The
\textbf{base-agreement set} is
\[
 E_{\mathrm{base}}=\{x:N_C=N_R\ \text{and} \Delta_j\le\tau_j\ \text{for every}\ j\in J\}.
\]
Here $J=\{t,R,\mathrm{tp},\mathrm{nvtl}\}$, with
$\tau_t=10^{-4}\,\mathrm{m}$, $\tau_R=10^{-5}\,\mathrm{rad}$, and
$\tau_{\mathrm{tp}}=\tau_{\mathrm{nvtl}}=10^{-4}$.
All quantities must also be finite. These fixed numerical-agreement thresholds are much
smaller than operational localization tolerances; they are comparison criteria, not
production acceptance limits.

Each map leaf receives a canonical identifier $(g,v)$, where $g$ is the ordinal of its
grid in the deterministically sorted map and $v$ is its signed voxel key. Before hashing,
each point's returned leaves are sorted by this identifier. A domain-separated SHA-256
digest preserves point and pass order while recording the sorted identifier list. The
\textbf{work-shape-conformant set}
$E_{\mathrm{shape}}\subseteq E_{\mathrm{base}}$ requires equal pass structure, points
per pass, neighbor-evaluation counts, and these per-point leaf-identity digests. Thus
\[
 W_{\mathrm{shape}}=(N_p,P_p,S_{\mathrm{nbr}},H_{\mathrm{ID}}).
\]
Here $H_{\mathrm{ID}}$ denotes the ordered chain of per-point canonical-ID digests.
A second SHA-256 payload digest includes each leaf ID, mean, and regularized inverse
covariance. It is reported independently and is not part of $E_{\mathrm{shape}}$.
This distinction prevents shape equality from being interpreted as equality of all
kernel operands.

Work-shape conformance is a dynamic check on each evaluated input. It does not imply full
semantic equivalence, membership in $D$, or equal total work. SHA-256 collision risk is
computational rather than a formal impossibility, and the selected payload still does not
record every execution state. C++ FLANN traversal, result containers, and allocation and
Rust kd traversal and flat buffers are outside $W_{\mathrm{shape}}$; each engine therefore
has a separate work-model instance. A conformant transferred fixture is a shared timing
witness, not proof of equal stress.

All synthetic fixtures satisfy the work-shape criterion, while none has an exact payload
digest. Real replay separates \realShapeAll{} work-shape-conformant,
\realBaseOnly{} base-only, and \realBaseDivergent{} frames outside
$E_{\mathrm{base}}$; \realIterationDivergent{} of the last group differ in iteration
count. An independent production-binary allocation count also reconstructs C++ point/pass
work to \allocCertSpreadPct\% on every neighbor-returning fixture, but does not establish
conformance of the full shape tuple.

\subsection{Analysis layer 3: Measurement and \pwcet}
Frozen little-endian fixtures feed both engines through one replay harness. An
\texttt{LD\_PRELOAD} interposer counts C++ allocations without source changes. Regression
against engine-specific counters is diagnostic only. Per-session POT/GPD fitting uses
maximum likelihood, bootstrap intervals, and a mandatory diagnostic gate; extrapolation is
reported only when assumptions hold.

\subsection{Cross-ISA transfer: Deployment-target validation}
\label{sec:meth-crossisa}
Pure-Rust \texttt{libm} removes dependence on the platform C library. Replaying frozen
fixtures on a Raspberry Pi~4 bare-metal \texttt{no\_std} kernel reproduces all
\raspiTotal{} counter tuples exactly after correcting one stale expected snapshot. This
checks each fixture rather than assuming ISA independence; Sec.~\ref{sec:eval-raspi4}
reports timing and Appendix~\ref{app:crossisa-debug} the discrepancy diagnosis.
