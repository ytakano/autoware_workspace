\subsection{The engines}
The C++ engine is Autoware's multigrid \ndt{}~\cite{autoware,ndtomp} (pcl-based, OpenMP;
measured serial, \texttt{num\_threads}=1). The Rust engine is a \texttt{no\_std}-capable port
exposing the same semantics; the differential test suite (voxel grid, align, engine,
end-to-end node paths) passes bit-exactly with the Rust engine substituted behind the C ABI.
Compiler versions appear in Sec.~\ref{sec:evaluation}. \todo{pin the exact autoware\_core /
port commits at camera-ready.}

\subsection{WCET-relevant hardening of the Rust RT path}
\begin{itemize}
  \item \textbf{Zero allocation from the first frame}: all align buffers are pre-reservable
    (\texttt{with\_capacity}) to their worst-case sizes ($P$, \maxnn, $N_{\mathrm{iter}}{+}1$);
    a counting global allocator asserts zero allocations \emph{including} the first frame ---
    a growth event is a WCET spike, so amortized warmup is not a bound.
  \item \textbf{Recursion-free kd-tree}: the radius search runs an iterative walk over a fixed
    64-entry stack (depth $\le \lceil \log_2 N \rceil{+}1$ by the median build). The exact
    near-then-far visit order is preserved --- neighbor order feeds float summation order,
    i.e.\ bit-exactness --- and is differential-tested against the recursive oracle. The
    iterative form measured ${\approx}12\%$ faster than the recursive one (same day, same core).
  \item \textbf{Panic-free, lock-free}: lint-enforced absence of panicking operations on the RT
    path; the align path takes no locks (lock-free snapshot of the map state).
  \item \textbf{Zero-cost instrumentation}: counter increments are compiled out when the
    feature is disabled; the disabled build's synthetic frame-time baseline is unchanged.
\end{itemize}

\paragraph{Sufficiency of the neighbor cap}
The port caps the radius search at $\maxnn = 64$ where the C++ engine collects an unbounded
neighbor set --- the cap is what makes the $P \cdot \maxnn \cdot N_{\mathrm{iter}}$
decomposition exist at all. Its value is justified geometrically. A leaf's centroid lies inside
its own voxel, and with the search radius equal to the voxel size (a coupling both engines'
APIs enforce), the search ball has diameter two voxels and thus intersects at most three cells
per axis: \emph{at most $3^3 = 27$ leaves per tile can ever be in range, regardless of map
content}. Under the disjoint-tile contract, leaf multiplicity is 1, so 27 bounds the global
count and $\maxnn = 64$ carries a $2.4\times$ margin --- truncation is unreachable and
bit-exactness with the uncapped C++ engine is unconditional. Exceeding 64 requires at least
three adversarially crowded \emph{overlapping} tiles; there the Rust engine truncates (its cost
stays bounded) while the C++ engine's cost grows without bound with tile multiplicity. The
equal-work assertion doubles as the truncation detector: \emph{dense-neighbors} sits exactly at
the cap ($8 \times 8 = 64$ in-range leaves) and passes, certifying the two engines still saw
identical neighbor sets.

\subsection{Adversarial fixture construction}
% The four hand-built generators + why multi-tile is needed for K=64 (single tile caps K at
% the <=8 voxels sharing a corner when radius == leaf size).
Four hand-built generators target one hazard each: \emph{dense-neighbors} (8 overlapping map
tiles whose voxel centroids crowd shared block corners, pinning $K = \maxnn = 64$ --- a single
tile geometrically caps $K$ at the ${\le}8$ voxels sharing a corner when the search radius
equals the leaf size, so tile overlap is essential);
\emph{max-iterations} (rough random surface, $\epsilon = 10^{-10}$, never converges);
\emph{cache-hostile} (wide map, shuffled source order); \emph{subnormal} (tight clusters with
the source on a shell where the kernel's $\exp$ lands in the \texttt{f64} subnormal range).
The search of Sec.~\ref{sec:meth-search} then composes and exceeds them.

\subsection{The deployment tier: a preprocessing-legal worst case}
\label{sec:impl-legal}
% These fixtures are engine-API-legal but NOT reachable through the production preprocessing
% pipeline. legal_worst is the hardest input that IS.
The fixtures above are \emph{engine-API-legal} but not \emph{preprocessing-reachable}: the
production pipeline voxel-downsamples the scan (leaf \SI{3.0}{m}; no duplicate points), caps it
at $P = 1500$ points (random downsample), and crops it to $\pm\SI{60}{m}$ --- and the map
pipeline emits disjoint, voxel-aligned tiles from a downsampled PCD, which limits leaf
multiplicity to 1 and hence $K$ to the ${\le}8$ voxels sharing a corner (the values are
Autoware's shipped localization defaults). We therefore add a fifth fixture,
\emph{legal-worst}: the hardest input satisfying all of these contracts --- a single tile whose
per-voxel points are spaced to survive map downsampling (centroids ${\approx}$ voxel centers,
$\sqrt{3} < 2.0$ from each lattice corner), and $P = 1500$ duplicate-free source points on
distinct lattice corners at \SI{4}{m} pitch inside the crop, each collecting exactly $K = 8$,
with $\epsilon = 10^{-10}$ pinning the iteration cap. Its counters certify the deployment
geometric ceiling: $\bar{K} = 8.0$ against the engine-level 64.

One axis of this fixture is deliberately \emph{not} production-parameterized: with the shipped
$\epsilon = 0.01$, its smooth lattice geometry converges in 2 iterations, so the fixture pins
the iteration cap through $\epsilon$ instead. Assuming the cap is nevertheless the right
deployment-tier choice --- and the assumption is not hypothetical: re-running the
counter-guided search with the \emph{parameters frozen to the shipped values} and every
candidate checked against the preprocessing contract found a fully legal rough-surface
geometry that oscillates to the full \textbf{30 of 30} iterations at $\epsilon = 0.01$
(frozen as \emph{legal-osc}; a per-candidate legality verifier enforces the one-point-per-cell,
crop, $P$, and map-spacing invariants independently of the generator). The production node
also ships an \emph{oscillation-count diagnostic} over the per-iteration pose array ---
machinery that exists precisely because non-convergence occurs in the field (feature-poor
geometry, map mismatch, coarse initialization guesses). Within this search family the two
worst axes resist combination: reaching $K = 8$ wants a smooth lattice (which converges
quickly), oscillation wants roughness (which scatters centroids, $\bar{K} = \legalOscKbar$),
so \emph{legal-worst} ($\epsilon$-pinned, higher total cost) remains the tier's time bound
and \emph{legal-osc} is its iteration-axis witness.
